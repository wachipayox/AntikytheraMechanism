# NeoForge/Minecraft 1.21.1 research for Mechanism Frames

## Scope and source of truth

This note covers the Minecraft/NeoForge side of phases 2–5: registration, frame state and shapes, normal `BlockItem` placement into a quadrant, persistence, removal and drops, mask enforcement, piston behavior, data/configuration and GameTests. Sable allocation, pose transforms and Sable Scale networking are deliberately left to the Sable-specific research.

All signatures below were checked against the exact sources generated by this workspace:

- Minecraft 1.21.1 + NeoForge 21.1.228 combined sources: `build/moddev/artifacts/neoforge-21.1.228-sources.jar`.
- FML loader 4.0.42 sources (for `ModConfigEvent` and `ModContainer`): `C:/Users/Wachii/.gradle/caches/modules-2/files-2.1/net.neoforged.fancymodloader/loader/4.0.42/207cf42087abc773f166dc95306edce5f8a538be/loader-4.0.42-sources.jar`.

Do not silently substitute a 1.21.2+ signature. Several relevant APIs changed around 1.21.

## Recommended decisions

1. Keep one authoritative, dimension-local `SavedData` manager. A frame BlockEntity is only a persisted/synced pointer to an assembly, not the owner of assembly contents.
2. Store six connection booleans in `BlockState`; precompute the 64 cage collision shapes. Graph membership must still be derived from actual adjacent frame blocks, never from those visual booleans.
3. Make the outline shape context-sensitive: cage normally; when a player holds an allowed `BlockItem`, add only the thin face-quadrant panels whose near mini cell is empty. This lets an empty quadrant be targeted without placing a full invisible cube in front of existing mini blocks.
4. Delegate placement to the original stack with `ItemStack#useOn(UseOnContext)` in the actual SubLevel. Do not recreate the target block state, item consumption, sound, components or placement hooks.
5. Centralize all frame evacuation in one idempotent transaction. Player, explosion, generic replacement and piston-destroy paths enter the same service with an explicit cause.
6. Use a scoped low-level `LevelChunk#setBlockState` guard for the FrameMask. NeoForge placement/fluid events do not cover all writes.
7. Do not claim vanilla piston movement while the frame has a BlockEntity. Vanilla 1.21.1 explicitly rejects every `BlockState#hasBlockEntity()` in its normal push path.

### Cage edge rule

For a cage made of its 12 edge bars, remove seams as follows:

- X-parallel edge: include only when both its Y-side and Z-side are exposed.
- Y-parallel edge: include only when both its X-side and Z-side are exposed.
- Z-parallel edge: include only when both its X-side and Y-side are exposed.

This removes the vertical separator in `[A][B]` while retaining the continuous outer edges. Cache the resulting collision/normal cage shape by the six-bit connection mask.

Recommended shape separation:

```java
getCollisionShape -> cage only
getOcclusionShape -> Shapes.empty()
getVisualShape    -> cage only
getShape          -> cage plus context-sensitive empty-cell target panels
```

`Properties#noOcclusion()` and `Properties#dynamicShape()` are appropriate. The latter is required once the outline shape depends on SubLevel occupancy/player context rather than only the BlockState.

### Why a full cube or one `EMPTY` boolean is incorrect

Ray picking uses `ClipContext.Block.OUTLINE`, which calls `BlockState#getShape`. Source: `net/minecraft/world/level/ClipContext.java` and `net/minecraft/world/level/BlockGetter.java`.

- A permanent full-cube `getShape` intercepts the ray before Sable can select an existing mini block.
- A cage-only shape cannot be hit through the center of an empty frame.
- A single `EMPTY` property works only for block one of eight. As soon as one mini block exists, the other seven empty positions become untargetable.

`CollisionContext` is an `EntityCollisionContext` during `Entity#pick`; its checked API is:

```java
@Nullable public Entity EntityCollisionContext#getEntity()
```

Therefore `getShape` can safely identify a `Player`, inspect both hands, and add thin panels only for allowed `BlockItem`s. Predefine 24 panels (six faces × four quadrants). For each exposed face, include a panel only when the corresponding near-layer mini position is air. An occupied near cell has no panel, so Sable's ray can reach the original mini block.

If the client has not received the assembly/SubLevel mapping yet, return only the cage. Never guess occupancy and block a real mini hit.

### Selected-cell outline

Source: `net/neoforged/neoforge/client/event/RenderHighlightEvent.java`.

Use `RenderHighlightEvent.Block` on `NeoForge.EVENT_BUS`. It is client-only and cancellable. When its hit is a frame target panel and the held block is allowed:

1. Reuse the same quadrant mapper used by placement.
2. Cancel the default frame outline.
3. Draw the selected 0.5 × 0.5 × 0.5 parent-space AABB with:

```java
LevelRenderer.renderLineBox(
        PoseStack poseStack,
        VertexConsumer buffer,
        AABB box,
        float red, float green, float blue, float alpha)
```

The event exposes `getCamera`, `getPoseStack`, `getMultiBufferSource` and `getTarget`. Obtain a line buffer with `RenderType.lines()` and translate by the negative camera position before drawing world coordinates.

## 3. Mapping a face hit to one of eight cells

For a hit location relative to the parent frame block:

```java
Vec3 f = hit.getLocation().subtract(frameX, frameY, frameZ);
int x = clamp(floor(f.x * 2), 0, 1);
int y = clamp(floor(f.y * 2), 0, 1);
int z = clamp(floor(f.z * 2), 0, 1);
```

Then force the normal-axis bit to the near layer:

```text
DOWN  -> y = 0       UP    -> y = 1
NORTH -> z = 0       SOUTH -> z = 1
WEST  -> x = 0       EAST  -> x = 1
```

Use a small clamp/epsilon at exactly `1.0`; a hit at a block corner must never produce bit `2`.

Assembly-local mapping remains:

```text
frameCell = framePos - assemblyOrigin
mini      = frameCell * 2 + (x, y, z)
```

Use `Math.floorDiv(miniCoordinate, 2)` for the inverse so negative local coordinates work.

## 4. Delegating normal `BlockItem` placement

Relevant sources:

- `net/minecraft/server/level/ServerPlayerGameMode.java`

- `net/minecraft/world/ItemInteractionResult.java`

Exact block hook:

```java
protected ItemInteractionResult useItemOn(
        ItemStack stack,
        BlockState state,
        Level level,
        BlockPos pos,
        Player player,
        InteractionHand hand,
        BlockHitResult hitResult)
```

Checked placement signatures:

```java
public InteractionResult ItemStack#useOn(UseOnContext context)

public UseOnContext(
        Level level,
        @Nullable Player player,
        InteractionHand hand,
        ItemStack itemStack,
        BlockHitResult hitResult)

public InteractionResult BlockItem#place(BlockPlaceContext context)
```

Prefer `stack.useOn`, not a direct state write and not normally `blockItem.place`, because `ItemStack#useOn` preserves NeoForge's `UseItemOnBlockEvent`, placement snapshots/hooks, Adventure checks and item-use stats before it reaches the original `BlockItem` implementation.

Server-authoritative flow:

1. Require `stack.getItem() instanceof BlockItem`.
2. Hard-deny a Mechanism Frame/anchor/service block before every configurable rule.
3. Evaluate `MiniaturizableRegistry` and `FrameMask`.
4. Resolve the selected mini air position.
5. Construct a mini-local `BlockHitResult` whose `blockPos` is that target air cell and whose direction is the outside face. `BlockPlaceContext` sees that air is replaceable and places at the hit cell itself.
6. Construct `UseOnContext` with the actual SubLevel as its explicit `level`. The two-argument constructor `new UseOnContext(player, hand, hit)` uses `player.level()` and is wrong unless Sable has explicitly swapped the player's Level.
7. Delegate with `stack.useOn(miniContext)`.
8. Verify the target state changed to the intended block before reporting success.

Sketch, with the Sable coordinate/temporary-player transform intentionally abstracted:

```java
BlockHitResult miniHit = new BlockHitResult(
        miniHitLocation,
        hit.getDirection(),
        targetMiniPos,
        false);

UseOnContext miniContext = new UseOnContext(
        subLevel,
        player,
        hand,
        stack,
        miniHit);

InteractionResult delegated = stack.useOn(miniContext);
```

Result policy:

- Allowed `BlockItem`, placed: convert `SUCCESS`/`CONSUME`/`CONSUME_PARTIAL` to the same `ItemInteractionResult` meaning.
- Allowed `BlockItem`, rejected or occupied: `ItemInteractionResult.FAIL`; do not let the item fall through and place against the parent frame.
- Other items: `PASS_TO_DEFAULT_BLOCK_INTERACTION` so normal block/item hooks remain available.

`ItemStack#consume(int, LivingEntity)` already respects `LivingEntity#hasInfiniteMaterials`, so direct original placement does not consume creative stacks.

All validation must run on the server even if the client predicts a valid panel. Never trust a client-provided mini index.


```text

```

1. If SavedData has the frame, SavedData wins and the BE is corrected.
2. If SavedData lacks the index but the BE points to a valid assembly that contains the frame, rebuild the index.
3. If neither side is valid, inspect the actual frame graph and create/recover an assembly.
4. Never perform linear UUID scans on every ray or tick; maintain both indexes.


`LevelTickEvent.Post` is on `NeoForge.EVENT_BUS`. Also clear purely in-memory caches/locks on `LevelEvent.Unload` or `ServerStoppingEvent`; do not store strong references to old levels in static maps.

Player destruction order in `ServerPlayerGameMode#destroyBlock` is:

```text
BlockEvent.BreakEvent
-> block.playerWillDestroy
-> copy/damage tool
-> state.onDestroyedByPlayer (actual removal)
-> block.playerDestroy (loot, only when harvestable)
```

`playerWillDestroy` is the last hook with the undamaged tool still in the player's hand. Snapshot `player.getMainHandItem().copy()` there and start/complete evacuation server-side. An optional `onDestroyedByPlayer` override can refuse frame removal if that transaction failed.

Explosion destruction calls `BlockState#onExplosionHit` for every affected position. Evacuate mini contents before calling `super.onExplosionHit`, while the frame still exists. Vanilla only adds `LootContextParams.EXPLOSION_RADIUS` for `DESTROY_WITH_DECAY`; both `ExplosionCondition` and `ApplyExplosionDecay` become non-lossy when that optional parameter is absent. Therefore explosion evacuation should intentionally evaluate mini loot without an explosion-radius parameter.

`onRemove` is still required as an idempotent fallback for `/setblock`, `/fill`, mod replacement and other direct state changes. Only react when `!state.is(newState.getBlock())`. Queue graph splitting until after the outer state change; evacuate the eight mini cells synchronously before their ownership disappears.

### One transaction API

```text
FrameEvacuationService.evacuate(
    ServerLevel parent,
    BlockPos framePos,
    EvacuationCause cause)
```

Suggested causes:

```text
PLAYER(player UUID/reference, copied tool)
EXPLOSION(explosion/source)
PISTON_DESTROY(direction)
GENERIC_REMOVAL
INTERNAL_MIGRATION(no drops; private only)
```

Required in-memory sequence:

```text
lock assembly/frame
-> reject duplicate transaction
-> resolve exactly eight owned mini positions
-> snapshot states + BlockEntities before any clear
-> calculate/capture drops
-> clear only those positions under private mask bypass
-> verify all eight are empty
-> update persistent ownership/index and mark dirty
-> spawn committed drops in the parent Level at transformed visual positions
-> queue graph split
-> mark complete/unlock
```

The idempotency key should be assembly UUID + frame position + manager revision. `onExplosionHit` followed by `onRemove` must not emit a second set of drops.

### Inventory/BlockEntity drops

`Block.getDrops` includes the `BLOCK_ENTITY` loot parameter but does not automatically reproduce every block's `onRemove` inventory behavior. For example, `ChestBlock#onRemove` calls `Containers.dropContentsOnDestroy`; furnaces and several other containers have their own removal paths.

Use a compatibility adapter boundary in the whitelist:

```text
MiniBlockEvacuationAdapter
  snapshotAuxiliaryDrops(...)
  prepareForClear(...)
  restoreOnRollback(...)
```

Default safe vanilla handling:

- Ordinary block: `Block.getDrops(state, subLevel, pos, be, breaker, tool)`.
- `Container` whose contents normally spill: copy/drain all slots into the transaction before clearing, so `onRemove` cannot spawn duplicates at plot coordinates.
- Shulker-like blocks whose contents are encoded into the block-item drop: dedicated adapter; do not also spill the inventory.
- Unknown modded inventory BE: deny by default until its compatibility adapter is registered.

For full NeoForge semantics, process each non-air mini block separately: convert that block's calculated stacks to local `ItemEntity` objects, construct and post one `BlockDropsEvent` with that block's state/position/BE, honor cancellation plus mutated drops/XP, then transform the accepted records to parent-world entities. An aggregate event for all eight cells would report the wrong state and BE. Do not call `CommonHooks.handleBlockDrops`, because it immediately adds entities to the SubLevel.

Player cause: check each mini state's `canHarvestBlock` before producing its normal block loot, and use the copied tool so Silk Touch/Fortune are evaluated by the real loot table. Inventory evacuation remains independent of tool correctness.

Explosion cause: deliberately omit explosion radius/decay and do not randomly discard generated stacks. The chosen policy for blocks that intentionally require a tool should be documented; the safest machine-recovery policy is to recover all non-decayed loot plus all inventories rather than emulate TNT loss.

## 8. FrameMask: no universal NeoForge placement event

Relevant sources:

- `net/minecraft/world/level/chunk/LevelChunk.java`
- `net/neoforged/neoforge/event/level/BlockEvent.java`
- `net/minecraft/world/level/material/FlowingFluid.java`
- `net/minecraft/world/entity/item/FallingBlockEntity.java`

The universal write point is:

```java
@Nullable
public BlockState LevelChunk#setBlockState(
        BlockPos pos, BlockState state, boolean isMoving)
```

`BlockEvent.EntityPlaceEvent` is not universal. Vanilla fluid spread calls `LevelAccessor#setBlock` directly, and a landing `FallingBlockEntity` also calls `Level#setBlock` directly. `FluidPlaceBlockEvent` covers lava/fire/fluid interactions, not all `FlowingFluid#spreadTo` writes.

Use a narrowly scoped cancellable HEAD injection into `LevelChunk#setBlockState` (or an equivalent Sable-provided hook if its exact source exposes one):

```text
if chunk.getLevel() is not an Antikythera-managed SubLevel -> do nothing
if new state is air -> allow cleanup
if new state is a hard-denied nested frame/service/portal block -> return null
if position belongs to FrameMask -> allow
if position belongs to the private service shell and block is an owned service block -> allow
if private migration/evacuation bypass token is active -> allow
otherwise -> return null without changing the chunk
```

`LevelChunk#getLevel()` is public in this version. The bypass must be a private, scoped `AutoCloseable`/`try-finally` token, not a public API flag.

This low-level guard is the last line of defense, not the only validation. Validate high-level actions before they partially mutate state:

- `BlockItem`: validate target before delegation.
- Pistons: cancel the entire move in `PistonEvent.Pre` if any destination is outside the mask.
- Falling blocks: when an entity exits the mask or a landing write is rejected, recover/drop it at the transformed parent position instead of leaving it to retry for hundreds of ticks.
- Fluids: low-level denial is sufficient for the write, but tests must verify that repeated scheduled ticks do not cause runaway work.

Mask lookup is:

```text
miniPos
-> floorDiv each axis by 2
-> FrameCell
-> assembly.frameCells.contains(FrameCell)
```

Hard nesting denial is checked before every tag/config/API allow and again in the low-level guard.

### Parent Mechanism Frame movement

The exact end of `PistonBaseBlock#isPushable` in 1.21.1 is:

```java
public static boolean isPushable(
        BlockState state,
        Level level,
        BlockPos pos,
        Direction movementDirection,
        boolean allowDestroy,
        Direction pistonFacing)

return !state.hasBlockEntity();
```

Therefore `pushReaction(PushReaction.NORMAL)` does not make a frame BlockEntity movable. The moving holder's checked constructor is `PistonMovingBlockEntity(BlockPos pos, BlockState blockState, BlockState movedState, Direction direction, boolean extending, boolean isSourcePiston)`: it persists `movedState`, direction and progress, but it does not serialize an arbitrary moved BlockEntity.

Safe choices:

1. **Phases 2–5, recommended:** keep the minimal frame BE and explicitly use `PushReaction.BLOCK` until phase 6. This prevents silent content loss and makes the current limitation honest.
2. **Safe destructive fallback:** use `PushReaction.DESTROY` and override `onDestroyedByPushReaction` to run the same evacuation transaction before the frame is cleared. The `DESTROY` branch returns before vanilla's BE rejection. Preflight this path in `PistonEvent.Pre` and cancel when evacuation cannot be guaranteed, because the later destroy callback cannot cancel an in-progress piston transaction. This is destruction, not movement.
3. **Phase-6 movement without a frame BE:** remove the frame BE and store all ownership in SavedData. Vanilla can then push the block. Capture source/destination sets in `PistonEvent.Pre` and finalize mapping after motion. Client assembly mapping needs a custom payload/data structure because no BE UUID remains.
4. **Phase-6 movement with the BE:** use a narrowly targeted mixin for `MechanismFrameBlock` only. Merely changing `isPushable` is insufficient. A persisted pending-move record must capture assembly UUID/source/destination before removal, survive a save during piston motion, restore the new frame BE when `PistonMovingBlockEntity` finishes, and drive the assembly pose from piston progress. Test chunk unload/reload mid-motion.

Do not patch vanilla to move arbitrary BlockEntities. Restrict any mixin to the frame block and keep Sable pose/assembly invariants in a dedicated adapter.

Moving one frame out of a connected component also changes topology; phase 6 must define whether the whole assembly moves or the moved subset splits before motion. Do not defer this decision to vanilla's block list.

## 12. Concrete phase 2–5 architecture

### Core types

```text
assembly/
  MechanismAssemblyRecord       immutable/persistable metadata
  MechanismAssemblyManager      SavedData + UUID/frame indexes + queue
  FrameGraph                    BFS/components from actual parent BlockStates
  AssemblyMergeService          prepare/copy/validate/commit/rollback
  AssemblySplitService          components + target allocation + transfer
  AssemblyTransferSnapshot      states, full BE tags, scheduled ticks

frame/
  MechanismFrameBlock
  MechanismFrameBlockEntity     UUID pointer only
  MechanismFrameShapes          64 cage shapes + 24 target panels
  FrameHitMapper                face hit -> cell bit -> mini position
  FramePlacementService         whitelist/mask + delegated BlockItem use
  FrameEvacuationService        all removal causes, idempotent
  MiniBlockEvacuationAdapter    inventory/mod compatibility

sublevel/
  MechanismSubLevelService      Sable allocation/find/remove
  MiniCoordinateMapper          constants + reversible mapping
  ManagedSubLevelIndex          Level identity -> assembly (O(1))
  FrameMask                     frame-cell set + service shell
  FrameMaskGuard                scoped low-level write check/bypass
  MiniPistonBoundaryGuard       PistonEvent.Pre

  MiniaturizableTags
  CompatibilityRegistration

client/

```

### Phase 2: one frame/one half-scale SubLevel

Deliver only:

- Registration and visible cage model (`RenderShape.MODEL`).
- Minimal pointer BE + dimension-local SavedData.
- One assembly with one frame and one SubLevel created at scale 0.5.
- Reversible 2 × 2 × 2 mapper.
- Context-sensitive empty-cell target panels.
- Original `BlockItem` delegated placement.
- Hard nested-frame deny.
- Save/load reconciliation.

Do not create an invisible normal block in one of the eight user positions to keep an empty SubLevel alive. If Sable requires a service anchor, reserve an explicit position outside the FrameMask service shell and hard-deny player selection/writes there.

### Phase 3: FrameMask

Add:

- `ManagedSubLevelIndex` and frame-cell mask.
- Low-level `LevelChunk#setBlockState` protection for managed SubLevels only.
- Private scoped bypass used by allocation/migration/evacuation.
- High-level item-placement validation.
- Piston preflight.
- Explicit falling-block recovery policy.
- Fluid/falling/piston stress tests.

### Phase 4: connected frames/merge

On placement, collect all distinct neighboring assembly UUIDs, not only the first. Cases:

```text
0 neighbors -> create assembly
1 neighbor  -> add frame
N neighbors -> add frame and transactionally merge all N assemblies
```

Choose the survivor deterministically (for example largest frame count, UUID tie-break). For source assembly origin `Os` and survivor origin `Ot`, the logical mini translation is:

```text
offset = 2 * (Os - Ot)
```

Transfer algorithm:

1. Snapshot every source-owned state and optional `BlockEntity#saveWithFullMetadata(registries)`.
2. Reserve/check all target cells before writing.
3. Write target states under bypass; recreate/load BEs with `BlockEntity#loadStatic(targetPos, state, fullTag, registries)` and `Level#setBlockEntity` when needed.
4. Copy scheduled block/fluid ticks.
5. Validate exact state/BE counts and IDs.
6. Update all frame UUID pointers/indexes.
7. Only then clear/remove source and commit SavedData.

Scheduled tick APIs are public in this version:

```java
public LevelTicks<Block> ServerLevel#getBlockTicks()
public LevelTicks<Fluid> ServerLevel#getFluidTicks()

public void LevelTicks#copyAreaFrom(
        LevelTicks<T> source, BoundingBox area, Vec3i offset)
public void LevelTicks#clearArea(BoundingBox area)
```

Call these for each disjoint 2 × 2 × 2 frame region so holes/service cells are not accidentally copied. `copyAreaFrom` preserves trigger tick, priority and sub-tick ordering.

When clearing a successfully copied source, suppress/discard source `onRemove` inventory drops via the compatibility adapter; `Block.UPDATE_SUPPRESS_DROPS` alone does not suppress container-specific `onRemove` spawns.

### Phase 5: evacuation/split

Removal pipeline:

1. Evacuate and clear only the removed frame's eight mini cells.
2. Remove its parent frame/index entry.
3. BFS the remaining actual frame positions.
4. Zero components: remove the SubLevel.
5. One component: keep the assembly; no transfer.
6. Multiple components: keep one deterministically and allocate one SubLevel per other component; transfer states/BEs/ticks transactionally.

Prepare all destinations before deleting any source data. If a target allocation or validation fails, keep the original assembly and report a hard error; never continue with half a split.

Batch same-tick removals (`/fill`, explosion) in the manager queue and compute final components once. Each frame evacuation remains individually idempotent.

## 14. Immediate hazards to avoid during the spike

- A `BaseEntityBlock` without `RenderShape.MODEL` is invisible despite valid blockstate/model JSON.
- A single global `EMPTY` state cannot represent eight independently empty cells.
- Selecting only the first adjacent assembly does not implement bridge merges.
- Removing the last frame/SubLevel before evacuating its eight cells permanently loses contents.
- Calling `new UseOnContext(player, hand, hit)` normally uses the parent `player.level()`, not the intended SubLevel.
- Calling `BlockItem#place` or `Level#setBlock` manually can bypass part of NeoForge's normal item-use path.
- `onRemove` alone has no tool/explosion cause; snapshot the player tool earlier and make all paths idempotent.
- `Block.UPDATE_SUPPRESS_DROPS` does not stop container-specific `onRemove` item spawning.
- `PushReaction.NORMAL` does not move a BlockEntity in vanilla 1.21.1.
- Low-level mask denial without piston preflight can leave a piston operation partially mutated.
- Treating all vanilla blocks as supported contradicts the compatibility boundary; begin with tested tags/adapters.
